# xdev Windows Pair 1.1.1

**简体中文** · [English](RELEASE-NOTES.en.md)

Windows Pair 1.1.1 按原信编号汇总投递进展。原生唤醒失败后，如果配对网关随后送达、目标聊天读信，发信方仍能看到已确认的结果。查询 `xdev msg status <原信编号>` 即可跟踪同一封信。[信件状态](../design/mail-lifecycle.md)

沿用原安装升级，两端保留配对和聊天绑定。使用配对目录网关的设备还需更新原网关的脚本，重启接收服务，并重连已加载旧版 xdev 的客户端。[升级步骤](README.md#升级回退与换机) · [配对网关](../design/paired-folder-mail.md)

## 从 1.0.3 升级可使用什么

- **从网页和窗口取材。** 在已授权的浏览器标签页或 Windows 窗口内读取文本、按控件引用操作，再回读结果。网页入口需要 OpenCode Browse 和已配对的扩展；Windows 窗口依赖登录桌面和应用提供的辅助功能。[网页与窗口](README.md#读取网页与应用窗口)
- **把信寄到另一个网络上的原聊天。** Windows 与 Linux 消息端可通过配对 SSH 直接交信，也可用自己的 GitHub 私仓临时保存端到端加密的信件。宿主支持到信事件时，可以唤醒空闲的原聊天。不同会话可同时交接，群信为每个收件人保留各自的进展和回复。[跨网络传递](../design/session-relay.md) · [私有信箱](../design/github-mail.md)
- **看清信到哪一步。** 发信前查询收件聊天最近一次已知状态，发信后按原信编号查看已读、处理进展和回信意向。任务改变时可请求撤回未读信或寄出修订。已处理信件可按需要本地归档，中继存储有独立的清理策略。[信件状态](../design/mail-lifecycle.md) · [保留与归档](../design/mail-retention.md)

## 已使用预览版？

沿用原有的配对和设备名，按安装手册升级，再在日常使用的客户端中单独重连 xdev。请聊天调用 `xdev_who`，核对设备和加载版本。若还需在空闲时接信，请用一封带主题的信在指定聊天之间验证已读和关联回复。[升级步骤](README.md#升级回退与换机) · [客户端验证](CLIENTS.md)

手册附有 Kimi Work 个人插件、豆包本地技能和 WSL 的接入方法。客户端工具页、模型实际调用和空闲聊天收信各有相应的验证步骤。浏览器自测可使用随包的[独立示例](../examples/isolated-browser/README.md)。历次预览改动见[版本记录](CHANGELOG.md)。
